# InnocenceCode Agent Harness 实施计划

为 InnocenceCode（Electron AI 聊天壳，当前后端为 mockAgent）构建可复用的 Agent Harness：**分层内核 + VS Code 风格显式扩展点（万物皆插件）**，双协议原生（OpenAI + Anthropic），完整权限体系，最终以**自举**（用它开发它自己）验收。

## 架构总览

npm workspaces 单仓（在 InnocenceCode 仓库内初始化 git）：

```
packages/
├── harness-core          # 内核：四接口 + AgentLoop + 上下文压缩 + 权限引擎 + PluginContext
├── provider-mock         # 剧本化 Mock Provider（离线开发/测试用，继承自 mockAgent 思路）
├── provider-openai       # OpenAI 兼容协议（fetch + SSE 流式 + tool call 增量解析）
├── provider-anthropic    # Anthropic 原生协议（messages API + tool_use 流式）
├── tools-fs              # Read / Write / Edit / Glob / Grep
├── tools-shell           # Bash/PowerShell 执行（超时、输出截断、按首词+子命令匹配规则）
├── plugin-subagent       # "Task" 工具：进程内嵌套 AgentSession（上下文隔离，权限沿用同一引擎）
├── plugin-skills         # SKILL.md 加载器（描述常驻索引、正文按需注入）
├── plugin-mcp            # MCP stdio 客户端（工具映射为 mcp__server__tool，默认 ask）
└── harness-electron      # 适配层：事件桥到现有 IPC + 审批 UI 通道 + 工作区选择 + JSONL 持久化
```

核心接口（harness-core 唯一开放面）：
- `Provider.chat(req): AsyncIterable<Delta>`（Delta = 文本增量 | 工具调用 | 用量）
- `Tool { name, description, readOnly, parameters(JSONSchema), execute(args, ctx) }`
- `Skill { name, description, loadBody() }`
- `PolicyRule.match(call): allow | ask | deny | skip`
- 插件导出 `activate(ctx: PluginContext)`，经 `ctx.registerTool/registerProvider/registerSkill/registerPolicyRule` 注册
- `AgentSession.run(input)` 驱动循环，发出类型化事件（token/toolCall/permissionRequest/toolResult/done），内核零 Electron 依赖

权限判定管线（短路）：`当前模式(auto/ask/plan) → 项目规则(.innocence/config.json，deny 优先，支持 Bash(npm test)、Edit(src/**) 参数匹配) → 会话授权(内存) → 默认 ask`。写类工具强制路径落在工作区内，逃逸即 deny；plan 模式只放行 readOnly。

上下文管理：token 估算超阈值时自动压缩（旧轮次总结为摘要，最近 N 轮保原文）。

## 实施步骤（里程碑顺序）

**第 0 步：文档与底座**
1. 设计文档写入 `docs/superpowers/specs/2026-08-18-agent-harness-design.md`（含本设计全部内容），规格自检后提交
2. `git init` + npm workspaces 配置：根 package.json、共享 tsconfig（strict）、vitest 工作区配置；把现有 src/ 保持不动

**M1：内核循环跑通（纯 Node）**
3. harness-core：类型定义（Delta/ChatRequest/ToolResult/事件）、AgentLoop（流式收集→逐工具权限判定→执行→回填→再 chat 直至最终回答）、PluginContext 与插件注册表、权限引擎（纯函数 + 可注入决策器）、token 估算与自动压缩
4. provider-mock：支持剧本（按轮次返回预定义 tool call 序列与流式文本）
5. tools-fs：五个文件工具（Read 带行号、Edit 精确替换+唯一性校验、Write、Glob、Grep），工作区根目录约束
6. vitest：循环确定性测试（剧本 Mock）、权限引擎全分支单测、tools-fs 在临时目录的真实文件测试

**M2：双协议 Provider**
7. provider-openai / provider-anthropic：chat completions 与 messages API 的流式解析（含 tool call 增量聚合），API key 经配置传入
8. 用录制的真实 SSE 响应做夹具回放测试（无网络依赖），覆盖纯文本、文本+工具调用、多工具、错误四种流

**M3：Electron 接入（GUI 第一次真实干活）**
9. harness-electron 适配层：创建 AgentSession、事件桥到现有 `chat:delta/done/error`（现有 IPC 契约与 UI 基本不动）；替换 mockAgent 调用点（mockAgent 退役为 provider-mock）
10. 新增 IPC：`chat:permission`（审批卡片：工具名+参数摘要+本次允许/会话内允许/拒绝）与工作区文件夹选择；React 侧新增审批卡片组件与模型/工作区设置入口
11. JSONL 会话持久化（userData 下每会话一文件，追加写），sessions.ts 换文件实现、接口不变
12. 端到端冒烟：GUI 中让 agent 完成一次真实小任务（读文件→改文件→报告），全程流式+审批

**M4：shell + 子 agent + Skills**
13. tools-shell：跨平台命令执行（win32 用 cmd）、超时上限、输出截断、规则按命令首词+子命令匹配
14. plugin-subagent：Task 工具（内置 explore 只读型 / general 全能型），并发上限 3，子会话权限沿用同一引擎
15. plugin-skills：扫描 `.innocence/skills/` 与用户目录，frontmatter 解析，描述注入索引表、正文按需加载，支持 `/技能名` 调用

**M5：MCP**
16. plugin-mcp：stdio JSON-RPC 客户端，按配置拉起外部 server、工具映射、崩溃隔离（标记不可用并告知模型）

**M6：自举验收**
17. 用 InnocenceCode + 本 Harness 开发自身一个新功能（预定：给 tools-fs 新增一个工具并带测试），全程权限可观测；修复过程中暴露的问题；更新 README

## 关键约束
- harness-core 及所有插件包禁止依赖 Electron；harness-electron 是唯一碰 Electron 的包
- 每个包独立 `tsc --noEmit` 干净、vitest 绿，才进入下一里程碑
- 现有 IPC 契约（src/shared/ipc.ts）只增不改（新增 permission/workspace 通道）
